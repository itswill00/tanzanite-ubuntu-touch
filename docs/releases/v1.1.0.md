Ubuntu Touch 20.04 (Focal) / Halium 12 for the **Xiaomi Redmi Note 14 4G** (`tanzanite`, MediaTek Helio G99 / MT6789).

First versioned release. The port built and installed, but audio was degraded, the torch and vibration did nothing, and the camera crashed on open. **All four are addressed.**

## What was wrong, and why

All four symptoms had a single underlying cause that the port's documentation had misdiagnosed: **178 vendor kernel modules were missing**. They are not in `vendor_boot` — a stock `vendor_boot.img` was extracted and its 207 modules turned out to be exactly the set the repository already shipped. They live on the `vendor_dlkm` partition inside `super.img`.

```
firmware .tgz (7.3 GB)
└── images/super.img (6.6 GB sparse)
    └── simg2img → super.raw
        └── lpunpack → vendor_dlkm_a.img (EROFS)
            └── fsck.erofs → 202 modules, 178 of them missing here
```

Recovered from official firmware `OS2.0.214.0.VOGEUXM`. The shipped set went from 207 to **385**.

| Feature | Was | Cause |
| --- | --- | --- |
| **Camera** | Crashed on open | Whole ISP pipeline absent (`camera_isp`, `camera_mem`, `imgsensor_isp6s`, `mtk-composite`, autofocus, `sensorhub`). No `/dev/mtk_cam*` node existed, so the HAL dereferenced a null handle instead of failing cleanly. |
| **Audio** | Thin, quiet, distorted | MT6789 DSP chain absent (`snd-soc-mt6789-afe`, `snd-soc-mt6366`, `audio_ipi`, `adsp`, …), so PulseAudio fell back to a generic PCM route with no Aurisys processing. |
| **Torch** | Nothing happened | `flashlight`, `flashlights-mt6789-o7`, `mtk-pwm` absent, so `/sys/class/flashlight_core` never existed and the bridge's writes silently failed. |
| **Vibration** | Nothing happened | **Not a module bug.** `regulator-vibrator.ko` was loaded, but `hfd-service` calls `access()` on `/sys/class/timed_output/vibrator` and fell through to `VibratorDummy` without a udev rule. |

Two further bugs were found along the way:

- **The audio amplifier was misidentified.** The overlay claimed an RT5512 and pointed at libraries that exist nowhere on the device. The stock `aurisys_config.xml` names **`sia81xx_sixth`** — the real chip is a **SiA81xx**. The stock config (28.8 KB) and its 110 `audio_param` files are now shipped.
- **`console=tty0` was missing** from the kernel cmdline. UBports requires it; without it a failed boot produces no output at all, which is why this port was so hard to debug.

## Also fixed

- `modules.load` named 184 entries while 207 files shipped — 23 drivers were never loaded. Now generated from the shipped set: **385 entries, matching 385 files**.
- `modules-load.d/tanzanite.conf` listed 174 modules of which **150 had no file**, producing a boot-time error for each. Now generated; contains only the 2 that are valid.
- Audio policy advertised 44100 Hz on 39 profiles while the droid card was forced to 48000, forcing a CPU resample. Now 48000 only.
- The flashlight bridge probes five candidate node names and two write formats, and logs failures via syslog instead of failing silently.
- Rootfs URL switched from a dead CI job to the official `ubuntu-touch-rootfs/job/ubports/focal` artifact.

## Installation

Full instructions: [`docs/FLASHING_GUIDE_en.md`](https://github.com/itswill00/tanzanite-ubuntu-touch/blob/main/docs/FLASHING_GUIDE_en.md) · [Bahasa Indonesia](https://github.com/itswill00/tanzanite-ubuntu-touch/blob/main/docs/FLASHING_GUIDE_id.md)

**Non-negotiable prerequisites:**

1. Bootloader unlocked; custom recovery (OrangeFox/TWRP) with A/B + terminal support
2. Firmware **exactly** `OS2.0.214.0.VOGEUXM` — HyperOS 3.x must be downgraded first
3. `/data` formatted to **unencrypted ext4** — Ubuntu Touch cannot use F2FS or FBE here

Verify the download:

```bash
sha256sum -c tanzanite-ut20.04-halium12-v1.1.0-20261029-b4e45b1.zip.sha256
```

After flashing, the build is recorded on the device:

```bash
cat /etc/tanzanite-build.prop
```

## Verification status

**Verified structurally, not on hardware.** The modules are present and loadable per `modules.load`, every path the audio config references exists, and both consistency checkers pass with zero findings:

```
check_modules.sh        all module lists consistent, 7/7 hardware groups ok
check_device_config.sh  8/8 checks pass
vendor_boot cmdline     console=tty0 bootopt=64S3,32N2,64N2  (header v4)
vendor_boot ramdisk     385 .ko files, modules.load 385 entries
```

What has **not** been observed is driver binding and end-to-end function on a real device. Check these after flashing:

```bash
ls -l /sys/class/flashlight_core/flashlight/flashlight_torch
lsmod | grep -E 'snd-soc-mt6789-afe|snd-soc-mt6366|audio_ipi|adsp'
journalctl -b | grep -i aurisys
ls /dev/mtk_cam* 2>/dev/null
journalctl -u hfd-service | grep -i vibrator   # expect "legacy", not "dummy"
```

## Known limitations

- Not yet confirmed on hardware (see above)
- `systempart` is not set, so the installer provisions `/data/ubuntu` rather than using system-as-root
- Firmware lock-in: `OS2.0.214.0.VOGEUXM`; HyperOS 3.x uses a 6.12 kernel and must be downgraded
- Xiaomi has never released kernel source for tanzanite; the kernel is community GKI work (`iprjkt/evernight-gki`)
